# Sheepft 시뮬레이터와 solver

저장소 루트 `README.md`의 규칙을 그대로 구현한 C# 라이브러리와, 레벨을 검증하는 명령줄 실행기다.
폴더 이름 끝의 `~` 때문에 Unity는 이 폴더를 불러오지 않는다.

| 폴더 | 내용 |
| --- | --- |
| `Core/` | 시뮬레이터와 solver. UnityEngine에 의존하지 않는다 (.NET Standard 2.1, C# 9) |
| `Cli/` | 명령줄 실행기 `sheepft` |
| `Tests/` | 규칙별 단위 테스트 (xUnit) |
| `Samples/` | 시험용 레벨 |

.NET SDK 10이 필요하다. 아래 명령은 이 폴더에서 실행한다.

## 테스트

```bash
dotnet test
```

## 명령줄 실행기

```bash
dotnet run --project Cli -c Release -- solve ../stages.txt --stage 3
```

```bash
dotnet run --project Cli -c Release -- check ../stages.txt
```

```bash
dotnet run --project Cli -c Release -- play ../stages.txt --stage 3 --moves "R1> R1> C2^"
```

```bash
dotnet run --project Cli -c Release -- prune ../stages.txt --stage 3
```

| 명령 | 하는 일 |
| --- | --- |
| `solve` | 최적 턴 수, 최적 길이 해의 개수와 수순, 수순마다 일어난 이벤트, 의도 기믹을 쓰지 않는 해 |
| `check` | 모든 스테이지를 한 줄씩 검증. 문제가 있으면 종료 코드 1 |
| `play` | 수순을 따라 두며 턴마다 맵과 일어난 일을 출력 |
| `prune` | shift 포인트 정하기. 헤더의 shift는 무시하고 모든 줄을 양방향으로 연 뒤, 의도와 다른 해를 만드는 포인트만 뺀 조합을 찾아 헤더에 쓸 표기를 출력 |

- 스테이지 번호는 파일 안의 순서이고 1부터 센다.
- 수는 `R1→ R1← C2↑ C2↓` 또는 `R1> R1< C2^ C2v`로 적는다.
- `solve` 옵션: `--solutions K`(적어 줄 수순 개수), `--depth D`(탐색 턴 수), `--nodes N`(보관할 상태 수 한도)
- `prune` 옵션: `--slack S`(제한 턴을 최적 + S로 잡음. 생략하면 헤더의 제한 턴 − 별 3개 기준), `--remove K`(뺄 포인트의 최대 개수, 기본 4)

### shift 포인트 정하기

shift 포인트가 적으면 풀이가 뻔해진다. 그래서 줄을 모두 연 상태에서 시작해 꼭 빼야 하는 것만 뺀다.

1. 맵과 `@intent`를 쓴다. 헤더의 shift는 아무 줄이나 하나 적어 둔다.
2. `prune`을 돌린다. "뺄 포인트 없음"이면 출력된 shift 표기를 헤더에 옮긴다.
3. 포인트를 빼야 한다고 나오면 조합을 고른다. 여러 개를 빼야 하면 맵을 고쳐 지형으로 길을 막는 쪽이 낫다.
4. 헤더의 제한 턴과 `@stars`를 최적 턴에 맞춰 고치고 `check`로 확인한다.

## 레벨 파일

README 10절 표기를 그대로 읽는다. 한 파일에 레벨을 여러 개 이어 적을 수 있다.
solver만 쓰는 줄을 헤더 아래에 덧붙일 수 있고, 없어도 된다.

```
# 돌담 앞에서  shift: R1 : R, C2 : U  제한 6턴  목표 양 2
@desc 돌 앞에서는 밀려도 제자리입니다.
@intent SheepMerge
@stars 3 4
.   .   g   .
.S  .   .S  #
```

| 줄 | 뜻 |
| --- | --- |
| `@desc` | 플레이어용 설명 |
| `@intent` | 제한 턴 안의 모든 해에 나와야 하는 이벤트. 이름은 `Core/Events.cs`의 `Ev` |
| `@optimal` | 최적 길이의 모든 해에 나와야 하는 이벤트. 더 긴 해에는 없어도 된다 (예: `Wait`) |
| `@stars 3 4` | 별 3개 기준 턴(최적과 같아야 함), 별 2개 기준 턴 |
| `//` | 주석 |

- 헤더와 돌로 시작하는 맵 줄은 둘 다 `#`으로 시작한다. `shift`라는 말이 있으면 헤더로 읽는다.
- 길이가 짧은 맵 줄의 오른쪽은 빈칸(`x`)으로 채운다.

## solver가 구하는 것

너비 우선 탐색이다. 아무것도 움직이지 않는 shift(대기)도 수로 센다.

- **최적 턴 수**: 제한 턴 안에서 가장 짧은 해.
- **최적해 개수**: 수순 기준과 상태 경로 기준 두 가지. 빈 줄을 왼쪽으로 미는 것과 오른쪽으로 미는 것은 수순으로는 다르지만 결과 상태가 같으므로 상태 경로로는 하나다.
- **우회해**: `@intent`의 이벤트 하나하나에 대해, 그 이벤트가 일어나는 수를 금지하고 제한 턴까지 다시 탐색한다. 그래도 깨지면 그 기믹 없이 깨는 해가 있는 것이다.
- **의도해**: `@intent`의 이벤트를 모두 쓰는 가장 짧은 해. 우회해가 없으면 최적해와 같다.

같은 상태는 한 번만 탐색한다. 같은 칸의 같은 상태 오브젝트는 서로 바꿔도 같은 상태로 본다.

### 한계

- 넓게 트인 7×7 맵에 양방향 줄이 6개이고 동물이 여럿이면 상태가 수백만 개를 넘는다. 이 PC에서 600만 상태에 1분쯤 걸린다. 한도에 걸리면 출력에 표시되고, 그때의 "없음"은 믿을 수 없다.
- 후반 스테이지는 shift 가능한 줄과 방향을 줄여 탐색이 끝까지 돌도록 설계한다.

## Unity에서 쓰기

`Core/`의 `.cs` 파일을 `Assets/Scripts/` 아래로 복사하면 된다. 진입점은 둘이다.

- `Simulator.Step(level, state, move, log)`: 한 턴을 진행하고 결과와 이벤트를 돌려준다.
- `Game`: 턴 수, 제한 턴, 누적 이벤트를 관리하는 껍데기.

undo는 `GameState.Clone()`으로 턴마다 상태를 쌓아 두면 된다.
